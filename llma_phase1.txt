2. MODULE: llm (LLM Integration Base)
================================================================================
Đường dẫn: custom_addons/llm/
Version: 18.0.1.7.2
Depends: mail, web

--- MỤC ĐÍCH ---
Module nền tảng để kết nối với các LLM provider (OpenAI, Anthropic, Ollama,
Mistral, Replicate, FAL.ai, LiteLLM, DeepSeek, Grok...).

--- CÁC MODEL ---

A) llm.provider - Cấu hình Provider
   Fields:
   - name (Char, required, unique) : Tên provider
   - service (Selection, required) : Loại dịch vụ
     Giá trị: openai, anthropic, ollama, mistral, replicate, fal, litellm...
   - api_key (Char) : API key xác thực
   - api_base (Char) : Custom API endpoint (VD: http://localhost:11434 cho Ollama)
   - company_id (Many2one → res.company) : Phân quyền theo công ty
   - model_ids (One2many → llm.model) : Các model thuộc provider này

   Methods quan trọng:
   - chat(messages, model, stream, tools, prepend_messages, **kwargs)
     → Gọi LLM để chat, hỗ trợ streaming
   - embedding(texts, model)
     → Tạo vector embeddings từ text
   - generate(input_data, model, stream, **kwargs)
     → Tạo nội dung (ảnh, text...)
   - list_models() → Lấy danh sách model từ provider
   - action_fetch_models() → Import model vào Odoo
   - format_messages(messages) → Format message cho API
   - format_tools(tools) → Format tool definition cho API
   - _dispatch(method, *args, **kwargs)
     → Dynamic routing: tự gọi {service}_{method}()
     VD: openai_chat(), ollama_embedding()...

B) llm.model - Model AI
   Fields:
   - name (Char) : Tên model (gpt-4, claude-3, llama3...)
   - provider_id (Many2one → llm.provider) : Provider sở hữu
   - publisher_id (Many2one → llm.publisher) : Nhà phát hành
   - model_use (Selection) : Mục đích sử dụng
     Giá trị: chat, embedding, completion, multimodal, generation, image_generation
   - default (Boolean) : Model mặc định cho use case
   - details (Json) : Metadata chi tiết
   - parameters (Text), template (Text)

C) llm.publisher - Nhà phát hành model
   Fields: name, logo, description, official, frontier, model_ids

D) mail.message - Mở rộng thêm trường LLM
   Fields mới:
   - llm_role (Char, indexed) : 'user' | 'assistant' | 'tool' | 'system'
   - is_error (Boolean) : Đánh dấu lỗi, loại khỏi context gửi LLM
   - body_json (Json) : Dữ liệu cấu trúc cho tool messages

   Message Subtypes: llm.mt_user, llm.mt_assistant, llm.mt_tool, llm.mt_system

--- CÁCH HOẠT ĐỘNG ---
1. Tạo Provider → Nhập api_key + api_base
2. Fetch Models → Provider tự load danh sách model
3. Đánh dấu Default model cho từng use case (chat, embedding)
4. Gọi provider.chat() hoặc provider.embedding() → Auto dispatch đến đúng service

3. MODULE: llm_openai (OpenAI Provider Implementation) ★ MỚI
================================================================================
Đường dẫn: custom_addons/llm_openai/
Version: 18.0.1.4.0
Depends: llm, llm_tool, llm_training
External: openai (pip install openai)

--- MỤC ĐÍCH ---
Triển khai cụ thể OpenAI provider cho hệ thống LLM.
Đây là module BẮT BUỘC nếu muốn dùng OpenAI (GPT-4, GPT-4o, embeddings).
Cung cấp: chat completions, embeddings, streaming, vision/multimodal,
function calling format, fine-tuning, và message validation.

--- EXTENDS MODEL: llm.provider ---

Methods OpenAI-specific (tự động dispatch qua _dispatch()):

A) Client & Service:
   - openai_get_client()
     → Trả về OpenAI(api_key, base_url) client
     → Hỗ trợ custom api_base cho endpoint tương thích OpenAI
   - _get_available_services()
     → Đăng ký ("openai", "OpenAI")

B) Chat:
   - openai_chat(messages, model, stream, tools, prepend_messages, **kwargs)
     → Gọi client.chat.completions.create()
     → stream=True: trả generator (từng chunk)
     → stream=False: trả dict hoàn chỉnh
   - _openai_process_streaming_response(response_stream)
     → Generator yield: {"content": "chunk"} hoặc {"tool_calls": [...]}
     → Tự lắp ghép tool_calls fragments từ stream
   - _openai_process_non_streaming_response(response)
     → Yield: {"content": "text"} hoặc {"tool_calls": [...]}

C) Embedding:
   - openai_embedding(texts, model)
     → Tạo vector embeddings cho list texts
     → Trả về list of embedding vectors

D) Model Discovery:
   - openai_models(model_id=None)
     → Lấy danh sách model từ OpenAI API
   - _openai_parse_model(model)
     → Phát hiện capabilities tự động:
     Vision/Multimodal patterns: gpt-4o, gpt-4-turbo, gpt-4.1,
                                  gpt-4-vision, gpt-5, o1, o3

E) Fine-tuning (delegate qua llm_training):
   - openai_upload_file(file_tuple, purpose="fine-tune")
   - openai_create_training_job(training_file_id, model_name, hyperparameters)
   - openai_retrieve_training_job(job_id)
   - openai_cancel_training_job(job_id)
   - openai_start_training_job(job) → Workflow: upload → create job
   - openai_check_training_job_status(job) → Poll + update model status
   State mapping: validating_files→validating, running→training,
                  succeeded→completed, failed→failed, cancelled→cancelled

--- MESSAGE FORMATTING (mail.message extension) ---

Method: openai_format_message()

User message format:
{
  "role": "user",
  "content": [
    {"type": "text", "text": "nội dung"},
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}},
    {"type": "file", "file": {"filename": "doc.pdf", "file_data": "data:..."}},
    {"type": "input_audio", "input_audio": {"data": "...", "format": "pcm"}}
  ]
}

Assistant message format:
{
  "role": "assistant",
  "content": "câu trả lời",
  "tool_calls": [
    {
      "id": "call_123",
      "type": "function",
      "function": {"name": "tool_name", "arguments": "{\"param\": \"value\"}"}
    }
  ]
}

Tool response format:
{
  "role": "tool",
  "tool_call_id": "call_123",
  "content": "{\"result\": ...}"
}

--- ATTACHMENT HANDLING ---
- Text files: Chèn nội dung plaintext (mọi model)
- Images (JPEG/PNG/GIF/WebP): Base64 data URL (chỉ multimodal model)
- PDF: Base64 file_data (chỉ multimodal model)
- Audio (PCM): input_audio blocks (model hỗ trợ audio)

--- TOOL FORMAT CHO OPENAI ---

openai_format_tools(tools) → Chuyển llm.tool thành:
{
  "type": "function",
  "function": {
    "name": "tool_name",
    "description": "mô tả tool",
    "parameters": {
      "type": "object",
      "properties": {"param": {"type": "string", "description": "..."}},
      "required": ["param"]
    }
  }
}
- Tự patch recursive schema (thêm type cho items)
- Tool choice mặc định: "auto"

--- MESSAGE VALIDATOR ---

OpenAIMessageValidator class (utils/openai_message_validator.py):
- Validate role field tồn tại trên mọi message
- Validate content không rỗng
- Validate tool messages có matching assistant tool_calls
- Loại bỏ tool messages mồ côi (không có assistant tương ứng)
- Loại bỏ user messages xen giữa tool_calls và tool responses
- Đảm bảo sequence hợp lệ cho OpenAI API

--- CẤU HÌNH ---
1. Tạo Provider trong Odoo: service="openai"
2. Nhập API Key: sk-xxxxxxx
3. API Base: để trống (mặc định api.openai.com)
   hoặc custom URL cho endpoint tương thích (Azure, local proxy...)
4. Click "Fetch Models" → tự import tất cả model (GPT-4o, embeddings, etc.)
5. Đánh dấu Default: chat=gpt-4o, embedding=text-embedding-3-small

5. MODULE: llm_knowledge (RAG Knowledge Base) ★ QUAN TRỌNG NHẤT
================================================================================
Đường dẫn: custom_addons/llm_knowledge/
Version: 18.0.1.1.0
Depends: llm, llm_store
External: requests, markdownify, PyMuPDF, numpy

--- MỤC ĐÍCH ---
Hệ thống RAG (Retrieval-Augmented Generation) hoàn chỉnh:
- Xử lý tài liệu (PDF, web, text, Odoo records)
- Chunking (chia nhỏ)
- Embedding (vector hóa)
- Semantic search (tìm kiếm ngữ nghĩa)

--- CÁC MODEL ---

A) llm.resource - Tài liệu nguồn
   Fields:
   - name (Char, required)
   - model_id (Many2one → ir.model) : Model Odoo liên quan
   - res_model (Char) : Tên model
   - res_id (Integer) : ID record
   - content (Text) : Nội dung markdown
   - collection_ids (Many2many → llm.knowledge.collection)
   - state (Selection) : Trạng thái pipeline
     Giá trị: draft → retrieved → parsed → chunked → ready
   - chunker (Selection) : Phương thức chia chunk (default: "default")
   - target_chunk_size (Integer, default=200) : Kích thước chunk (tokens)
   - target_chunk_overlap (Integer, default=20) : Overlap giữa chunks
   - parser (Selection) : Phương thức parse (default, json)
   - retriever (Selection) : Phương thức lấy dữ liệu (default, http)
   - chunk_ids (One2many → llm.knowledge.chunk)
   - lock_date (Datetime) : Lock xử lý concurrent

   Methods pipeline:
   - process_resource() : Chạy toàn bộ pipeline từ state hiện tại
   - retrieve() → retrieved : Lấy nội dung từ nguồn
     + retrieve_default() : No-op
     + retrieve_http() : Fetch URL, follow redirect, meta refresh
   - parse() → parsed : Chuyển đổi sang markdown
     + _parse_pdf() : PyMuPDF, OCR text + images
     + _parse_html() : HTML → Markdown (markdownify)
     + _parse_text() : Plaintext passthrough
     + _parse_image() : Image reference
     + parse_json() : Odoo record → JSON/Markdown
   - chunk() → chunked : Chia nhỏ document
     + _chunk_default() : Sentence-based chunking
       - Tách câu theo regex (.!? boundaries)
       - Ước tính tokens (1 token ≈ 4 ký tự)
       - Sliding window với overlap
   - embed() → ready : Tạo vector trong store

B) llm.knowledge.collection - Bộ sưu tập Knowledge
   Inherits: llm.store.collection, mail.thread
   Fields:
   - name (Char, required, tracked)
   - description (Text)
   - embedding_model_id (Many2one → llm.model, required)
     → BẮT BUỘC chỉ định model embedding (text-embedding-ada-002, etc)
   - resource_ids (Many2many → llm.resource)
   - domain_ids (One2many → llm.knowledge.domain)
   - resource_count, chunk_count (computed)
   - default_chunk_size (Integer, default=200)
   - default_chunk_overlap (Integer, default=20)
   - default_chunker, default_parser (Selection)

   Methods:
   - sync_resources() : Đồng bộ resource theo domain filter
   - process_resources() : Chạy pipeline cho tất cả resource
   - reindex_collection() : Xóa + tạo lại vector store
   - _initialize_store() : Khởi tạo vector store

C) llm.knowledge.chunk - Mảnh dữ liệu đã chia
   Fields:
   - name (computed) : "{resource_name} - Chunk {sequence}"
   - resource_id (Many2one → llm.resource, cascade)
   - sequence (Integer)
   - content (Text, required) : Nội dung chunk
   - metadata (Json) : Metadata bổ sung
   - collection_ids (Many2many, related từ resource)
   - embedding (Char, virtual) : Input cho vector search
   - similarity (Float, computed) : Điểm tương đồng

   Methods (VECTOR SEARCH):
   - search() : Override để hỗ trợ vector search
   - _search_embedding() : Custom search handler
   - _vector_search_aggregate() : Search across nhiều collection
   - _generate_embeddings_for_collections() : Tạo embedding

D) llm.knowledge.domain - Bộ lọc tự động
   Fields:
   - collection_id (Many2one → llm.knowledge.collection)
   - model_id (Many2one → ir.model) : Model mục tiêu
   - domain (Char, default="[]") : Domain filter expression
   - active (Boolean)

--- PIPELINE RAG ---

  Nguồn dữ liệu (PDF/URL/Odoo Record)
         ↓
  [1. RETRIEVE] Lấy nội dung thô
         ↓
  [2. PARSE] Chuyển sang Markdown
         ↓
  [3. CHUNK] Chia thành đoạn nhỏ (200 tokens, overlap 20)
         ↓
  [4. EMBED] Tạo vector embedding qua LLM model
         ↓
  [5. STORE] Lưu vector vào Qdrant/pgvector/Chroma
         ↓
  [SEARCH] Semantic search: query → embedding → similarity search

--- WIZARDS ---

A) CreateRAGResourceWizard
   - Tạo resource từ record Odoo đã chọn
   - Template: {record_name}, {model_name}, {id}
   - Có thể process ngay

B) UploadResourceWizard
   - Upload file hoặc nhập URL
   - Template: {filename}, {collection}, {index}
   - Hỗ trợ multi-file

6. MODULE: llm_knowledge_automation (Auto-Sync Knowledge)
================================================================================
Đường dẫn: custom_addons/llm_knowledge_automation/
Version: 18.0.1.0.0
Depends: llm_knowledge, base_automation

--- MỤC ĐÍCH ---
Tự động đồng bộ knowledge base khi dữ liệu Odoo thay đổi.
"Set and forget" - không cần sync thủ công.

--- CÁCH HOẠT ĐỘNG ---

Mở rộng 2 model:

A) base.automation - Thêm action type "llm_update"
   Fields mới:
   - state: Thêm giá trị "llm_update"
   - llm_collection_id (Many2one → llm.knowledge.collection)
   - llm_auto_process (Boolean, default=True)

   Method: _process_llm_update(records)
   1. Lọc record theo domain filter
   2. Tìm llm.resource theo (model_id, res_id)
   3. Nếu tồn tại → thêm vào collection
   4. Nếu chưa có → tạo resource mới
   5. Nếu llm_auto_process=True → chạy process_resource()
   6. Record không match → xóa khỏi collection

B) llm.knowledge.collection - Thêm auto-sync
   Fields mới:
   - automated_sync (Boolean) : Bật auto-sync
   - automation_ids (One2many → base.automation)
   - auto_process_resources (Boolean, default=True)

   Method: sync_automated_actions()
   - Tạo 3 automation cho mỗi domain filter:
     + on_create : Mọi record mới → tự thêm vào knowledge
     + on_write  : Record thay đổi → kiểm tra domain, thêm/xóa
     + on_unlink : Record bị xóa → xóa khỏi knowledge

--- LUỒNG TỰ ĐỘNG ---

  Domain Filter (trong collection)
       ↓
  sync_automated_actions() → Tạo base.automation records
       ↓
  Trigger: Record được tạo/sửa/xóa trong Odoo
       ↓
  _process_llm_update() → Tạo/cập nhật/xóa llm.resource
       ↓
  [Nếu auto_process] → process_resource() (full RAG pipeline)
       ↓
  Knowledge Base luôn cập nhật!

VÍ DỤ:
- Domain filter: model=product.product, domain=[('sale_ok','=',True)]
- Khi thêm sản phẩm mới có sale_ok=True → auto tạo resource → auto embed
- Khi sửa sản phẩm thành sale_ok=False → auto xóa khỏi collection

8. MODULE: llm_tool (Function Calling & Tool Execution)
================================================================================
Đường dẫn: custom_addons/llm_tool/
Version: 18.0.4.1.2
Depends: base, mail, llm
External: pydantic>=2.0.0, mcp

--- MỤC ĐÍCH ---
Framework cho AI gọi hàm (function calling) và tương tác với Odoo database.

--- MODEL CHÍNH: llm.tool ---
Inherits: mail.thread

Fields:
- name (Char, required, unique) : Tên tool
- description (Text, required) : Mô tả gửi cho LLM
- implementation (Selection, required) : Loại implementation
  Giá trị:
  + function : Python method có decorator @llm_tool
  + odoo_record_retriever : Truy vấn record
  + odoo_record_creator : Tạo record
  + odoo_record_updater : Cập nhật record
  + odoo_record_unlinker : Xóa record
  + odoo_model_inspector : Xem cấu trúc model
  + odoo_model_method_executor : Chạy method bất kỳ
- input_schema (Text) : JSON Schema cho parameters
- requires_user_consent (Boolean) : Cần xác nhận user
- default (Boolean) : Include trong mọi LLM request
- MCP Annotations:
  + read_only_hint, idempotent_hint, destructive_hint, open_world_hint

Methods:
- execute(parameters) : Validate + chạy tool
- get_input_schema() : Lấy/generate JSON schema
- get_tool_definition() : MCP-compatible definition
- _register_hook() : Scan @llm_tool decorators khi startup
- _sync_tools_to_db() : Đồng bộ decorator → DB records

--- CÁC TOOL CÓ SẴN (Built-in) ---

1. odoo_record_retriever
   - Input: model, domain, fields, limit
   - Output: Danh sách record dicts
   - VD: Tìm tất cả sale.order có state='sale'

2. odoo_record_creator
   - Input: model, fields, records
   - Output: ID + display_name records đã tạo

3. odoo_record_updater
   - Input: model, domain, values, limit(default=1)
   - Output: Số record đã update

4. odoo_record_unlinker
   - Input: model, domain, limit(default=1)
   - Output: Thông tin record đã xóa

5. odoo_model_inspector
   - Input: model name, filters
   - Output: Fields, methods, inheritance info

6. odoo_model_method_executor
   - Input: model, method, record_ids, args, kwargs
   - Output: Kết quả method

--- TOOL EXECUTION FLOW ---
LLM Response (function_calls)
  → Mail Message (llm_role="assistant", body_json chứa tool_calls)
  → post_tool_call() → Tạo tool message (status="requested")
  → execute_tool_call() → status="executing"
  → tool.execute(arguments) → Validate + chạy
  → status="completed" hoặc "error"
  → Kết quả trả về cho LLM tiếp tục conversation

--- DECORATOR @llm_tool ---
Dùng trong model bất kỳ:

  from odoo.addons.llm_tool.tools import llm_tool

  class SaleOrder(models.Model):
      _inherit = 'sale.order'

      @llm_tool(name="get_order_total", description="Get order total")
      def get_total(self, order_id: int) -> dict:
          order = self.browse(order_id)
          return {"total": order.amount_total}

→ Tool tự đăng ký vào DB khi Odoo khởi động

Parameters:

- collection_id (int, required) : ID collection cần search
- top_k (int, default=5) : Max chunks mỗi resource
- top_n (int, default=3) : Max resource khác nhau

Luồng xử lý:
1. Validate collection tồn tại
2. Tính search_limit = top_n * top_k * 2
3. Gọi chunk.search(args=[("embedding","=",query)], ...)

4. Group chunks theo resource
5. Chọn top_n resource có similarity cao nhất
6. Mỗi resource lấy top_k chunks
7. Return kết quả:

Output format:
{
  "query": "search text",
  "collection": "Tên collection",

  "results": [
    {
      "content": "Nội dung chunk...",
      "resource_name": "Tên tài liệu",
      "resource_id": 456,
      "chunk_id": 789,
      "similarity": 0.9523,
      "similarity_percentage": "95%"
    }
  ],
  "total_chunks": 5,
  "embedding_model": "text-embedding-ada-002"
}

Để tối ưu dữ liệu gửi vào RAG, override method trên model:

class ProductProduct(models.Model):
    _inherit = 'product.product'

    def llm_get_fields(self):
        """Chỉ định fields nào đưa vào knowledge base"""
        return {
            'name': self.name,
            'default_code': self.default_code,
            'list_price': self.list_price,
            'description': self.description_sale or '',
            'categ_id': self.categ_id.name,

--- PERFORMANCE TIPS ---

1. Dùng Qdrant cho production (nhanh hơn pgvector nhiều lần)
2. Chunk size 200-300 tokens là tối ưu cho hầu hết use case
3. Overlap 10-20% chunk size
4. Dùng text-embedding-3-small thay text-embedding-ada-002 (rẻ hơn, tốt hơn)
5. Batch process: Xử lý resource theo batch, không chạy hết 1 lúc
6. Auto-sync nên bật cho data thay đổi thường xuyên
7. Reindex khi thay đổi embedding model

Embedding:
- text-embedding-3-small: $0.02/1M tokens
- 10,000 sản phẩm × ~200 tokens = 2M tokens ≈ $0.04

Chat:
- gpt-4o: $2.50/1M input, $10/1M output
- Mỗi query RAG ≈ 2000 tokens input ≈ $0.005/query

→ Rất kinh tế cho knowledge base quy mô vừa.
